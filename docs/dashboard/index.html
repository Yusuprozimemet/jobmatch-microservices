What the vectors say

How the vectors are built

Snapshots. The initial commit plus every first-parent merge on main (). Code PRs, spec-change PRs and close-the-day PRs are told apart by branch name and title.

Drift uses the full spec text: word frequencies (log-scaled) of plan.md and specs/*.md, compared by angle with the Sep 20 version. Each word is weighted by how few of the Sep 20 files used it, so words every file uses (“the”, “day”) count for nothing and a rewrite is not diluted by them. 0° means unchanged, 90° means nothing in common.

Gap needs a space both sides share. It is built from the code-like names the specs put in backticks (SavedJobCounts, saved_jobs, JobRepository…). The spec vector counts how often each name appears in the specs. The code vector counts how often it appears in the code, with Markdown, data/, screenshots and comment lines left out: a comment naming a thing is not the thing. Both are log-scaled and compared by angle. Each merge’s gap uses only the names the specs had used by that merge, so a name a later spec adds does not move an earlier point.

The plane is a principal-component projection of all vectors (one spec and one code vector per snapshot) together. PC1 holds of the variance and PC2 holds , so distances in the plot are faithful but not exact.

Refresh. python scripts/spec-drift.py --build in the repository writes this page with its data. It is rerun after every merge, before the next step starts.

Limits. Names in a spec that should disappear (like saved_jobs leaving jobs/) still count as shared vocabulary. Comments are recognised by line (//, /*, *, --, #, <!--), not parsed, so a marker inside a string can hide the code after it on that line. The gap measures shared language, not correctness; correctness lives in the acceptance criteria and the tests.
